# Campus Connect (Draft)

CS5910 System Design and Implementation — Julio Larrea, Muiz M. Onifade, Pavel Clarke.

Contains the MySQL database schema, generated project data for every table, a working login screen, dashboard pages for
each role, student sign-up and password reset, student registration (add/drop) and admin course-section creation. See [DEMO.md](DEMO.md) for the midterm demo.

## How it is built

| Part | Technology | Where |
|---|---|---|
| Front end | HTML, CSS, JavaScript | `public/` |
| Back end | **PHP 8** (PDO for MySQL, PHP sessions, `password_hash` for passwords) | `api/` |
| Database | MySQL 8 | `db/` |
| Web server | nginx + PHP-FPM on Amazon Lightsail (Ubuntu) | `deploy/` |

## Run it on your own computer

Requires PHP 8.1+ (with the `pdo_mysql` extension) and MySQL 8.0+.

```bash
# Create the database and load all the data:
mysql -u root -p < db/Database_schema.sql
mysql -u root -p campus_connect < db/Project_data.sql
# Create a MySQL user for the website (once):
mysql -u root -p -e "CREATE USER 'campus'@'localhost' IDENTIFIED BY 'campus'; GRANT ALL ON campus_connect.* TO 'campus'@'localhost';"
# Start PHP's built-in web server, then open http://localhost:3000
php -S localhost:3000 -t public api/index.php
```

Connection settings default to user `campus` / password `campus` on `127.0.0.1`; change them with the environment
variables `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`.
To put it online on Amazon Lightsail, see [DEPLOY-LIGHTSAIL.md](DEPLOY-LIGHTSAIL.md).

## Project data

`db/Database_schema.sql` matches *Design of the Database — e. Database Schema* in the System Manual (40 relations).
`db/Project_data.sql` is generated by `db/generate-data.js` (run with `node db/generate-data.js`; it needs Node.js and PHP, and only
matters if you want to regenerate the data) and follows the SRS rules, e.g.
full-time faculty teach at most 2 sections and part-time exactly 1, at most 10 students per section, sections with
fewer than 5 students were cancelled before the semester started, prerequisites, credit limits, no time clashes,
no registration with an active hold, at most 15 advisees per full-time advisor.
`db/validate.sql` checks all of these against the loaded data (every row should show 0 violations).

| What | Rows |
|---|---|
| Users / logins | 305 (240 students, 60 faculty, 3 admins, 2 statistics dept) |
| Departments / majors / minors | 6 / 12 / 6 |
| Buildings / rooms / offices | 5 / 30 / 70 |
| Courses / prerequisites | 90 / 96 |
| Semesters | 6 (Fall 2024 – Spring 2027; Fall 2026 is current; Spring 2027 registration opened Oct 1, 2026) |
| Course sections | 333 |
| Enrollments / student history | 2,027 / 1,447 |
| Attendance (Fall 2026 so far) | 5,746 |
| Audit log | 30 |

`db/sample-queries.sql` has example queries tied to SRS requirements (schedule, transcript, roster, advisees, holds, seats, Stat-Dept reports, audit log).

| Path | What it is |
|---|---|
